# Domain Docs

## Before exploring

Read `GLOSSARY.md` at the repo root and any relevant ADRs in `docs/adr/`. If either is absent, proceed silently; `/domain-modeling` creates them when terms or decisions are resolved.

## Layout

This is a single-context repository: use one root `GLOSSARY.md` and system-wide ADRs in `docs/adr/`.

## Use the glossary's vocabulary

Use terms as defined in `GLOSSARY.md` in issue titles, proposals, hypotheses, and tests. If a concept is missing, reconsider whether it belongs in the project's language or note the gap for `/domain-modeling`.

## Flag ADR conflicts

Surface any contradiction with an existing ADR explicitly rather than silently overriding it.
